# نام سرویس
سرویس Create Financial Institution Transfer Message

## شرح سرویس و قوانین کسب و کار

این سرویس مسئول دریافت اطلاعات کسب‌وکاری مورد نیاز برای انتقال وجه بین مؤسسات مالی و ایجاد یک پیام مالی استاندارد جهت ارسال به شبکه پیام‌رسان انتخاب‌شده است.

سرویس باید بدون وابستگی مصرف‌کننده به ساختار فنی پیام، اطلاعات دریافتی را دریافت کرده، اعتبارسنجی کند و بر اساس Message Definition فعال، پیام خروجی مناسب را ایجاد نماید.

سرویس **دریافت درخواست ساخت پیام 200** به‌منظور ایجاد یک پیام انتقال وجه بین مؤسسات مالی طراحی شده است. این سرویس اطلاعات کسب‌وکاری موردنیاز برای انتقال وجه را از سامانه‌های متقاضی دریافت کرده و بدون وابسته کردن آن‌ها به ساختار پیام‌های استاندارد، درخواست ایجاد پیام را پردازش می‌کند.

پس از دریافت درخواست، Platform اعتبارسنجی‌های فنی لازم را بر روی اطلاعات ورودی انجام داده، Message Definition مناسب را بر اساس نوع پیام، شبکه ارتباطی و تنظیمات فعال انتخاب می‌کند و سپس پیام استاندارد متناظر را ایجاد می‌نماید. پیام ایجادشده به‌صورت یک **Message Instance** در سامانه ثبت شده و در وضعیت **Draft** قرار می‌گیرد تا در صورت نیاز قبل از ارسال ویرایش، تکمیل یا مجدداً اعتبارسنجی شود.

مسئولیت این سرویس صرفاً مدیریت فرآیند ایجاد پیام، اعمال قوانین فنی، تولید ساختار استاندارد و مدیریت وضعیت پیام است و هیچ‌گونه اعتبارسنجی یا تصمیم‌گیری مرتبط با فرآیندهای کسب‌وکاری مانند کنترل مجوز انتقال، اعتبار حساب، موجودی، یا سایر قوانین تجاری را انجام نمی‌دهد. این مسئولیت‌ها بر عهده سامانه‌های کسب‌وکار استفاده‌کننده از سرویس است.

این سرویس به گونه‌ای طراحی شده است که مستقل از استاندارد پیام و شبکه پیام‌رسان بوده و بتواند از طریق **Message Definition** مناسب، برای یک درخواست کسب‌وکاری، پیام متناظر را در قالب‌های مختلف و بر بستر شبکه‌های متفاوت تولید کند؛ بدون آنکه قرارداد سرویس یا نحوه تعامل سامانه‌های کسب‌وکار تغییر کند.

## Validation عمومی سرویس

**وجود اطلاعات اجباری** — کنترل شود:
- Message Type ارسال شده باشد.
- Network مشخص باشد.
- مبلغ وجود داشته باشد.
- ارز مشخص باشد.
- تاریخ ارزش وجود داشته باشد.
- مؤسسه ارسال‌کننده مشخص باشد.
- مؤسسه دریافت‌کننده مشخص باشد.

**کنترل نوع داده**
- Amount باید عددی باشد.
- Currency باید مقدار معتبر داشته باشد.
- Date باید فرمت صحیح داشته باشد.
- Referenceها نباید دارای کاراکتر غیرمجاز باشند.

**کنترل مقدار**
- مبلغ باید بزرگ‌تر از صفر باشد.
- ارز باید از لیست ارزهای پشتیبانی‌شده باشد.
- تاریخ ارزش باید معتبر باشد.

## Validation اختصاصی Message 200

**کنترل ساختار پیام**
Platform باید بررسی کند که Message Definition مربوط به Message 200 فعال باشد.

**کنترل Sender Institution** — بررسی شود:
- مؤسسه ارسال‌کننده معتبر باشد.
- شناسه مؤسسه قابل تبدیل به ساختار پیام باشد.
- اطلاعات مورد نیاز برای تولید شناسه ارسال‌کننده موجود باشد.

**کنترل Receiver Institution** — بررسی شود:
- مؤسسه دریافت‌کننده معتبر باشد.
- اطلاعات لازم برای مقصد پیام وجود داشته باشد.
- مقصد برای شبکه انتخاب‌شده قابل ارسال باشد.

**کنترل Amount** — بررسی شود:
- مبلغ وجود داشته باشد.
- مبلغ صفر نباشد.
- تعداد رقم اعشار مطابق قوانین ارز باشد.
- طول مقدار با محدودیت Message Definition سازگار باشد.

**کنترل Currency** — بررسی شود:
- کد ارز معتبر باشد.
- ارز با شبکه انتخابی سازگار باشد.

**کنترل Value Date** — بررسی شود:
- تاریخ معتبر باشد.
- فرمت تاریخ صحیح باشد.
- تاریخ با قوانین Message Definition سازگار باشد.

**کنترل Reference** — بررسی شود:
- Reference وجود داشته باشد.
- طول آن مطابق محدودیت پیام باشد.
- کاراکترهای غیرمجاز نداشته باشد.

**کنترل Narrative** — در صورت وجود:
- طول متن کنترل شود.
- کاراکترهای غیرمجاز کنترل شوند.
- محدودیت‌های Message Definition رعایت شود.

**کنترل Mapping** — قبل از تولید پیام بررسی شود:
- تمام داده‌های مورد نیاز Message Definition دارای Mapping باشند.
- هیچ Field اجباری بدون مقدار نمانده باشد.
- Mapping نسخه فعال استفاده شود.
